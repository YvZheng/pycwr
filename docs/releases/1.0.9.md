# pycwr 1.0.9

This patch fixes failures in plotting and file export, and preserves missing-data masks in numerical workflows.

## Fixes

- Resolve bundled `copy_pyart_*` colormaps when a default field requests a `pyart_*` name. This fixes ZDR plotting without an installed Py-ART colormap registry ([#60](https://github.com/YvZheng/pycwr/issues/60)). Existing registered colormaps retain priority.
- Accept numeric longitude/latitude endpoints in vertical sections, update geographic tick labels after zooming, and use the correct labels and colorbar orientation. Fix field aliases, native-range CR/CAPPI plotting, RHI range-mode forwarding, rectangular coordinate grids, and non-cylindrical map projections.
- Interpolate coordinate edges only once when converting antenna vectors, including xarray inputs. Handle empty range rings, calm or empty VVP winds, missing wind-profile sample counts, and legacy custom colormap options.
- Preserve masked samples in QC, HID, wind retrieval, and CR/VIL/ET. Exclude missing interpolation neighbors, support array-form interpolation targets, and prevent ET from interpolating against missing-value sentinels. VAD sample counts now include coordinate and weight validity.
- Reject non-finite or non-positive gate spacing and effective Earth radii consistently in Python and compiled code. Support single-gate xarray inputs in the legacy attenuation interface.
- Preserve valid low and high moment values during WSR98D and NEXRAD MSG31 export by selecting consistent per-moment offsets and storage widths while retaining the original quantization scale. Reject unsupported range spacing and unrepresentable values instead of silently altering them.
- Fix scalar and multidimensional time conversion, write xradar datetime coordinates with NetCDF encoding, preserve file-stream format detection, and close reader-owned files after parse failures.
- Correct CC/SC ray azimuths, CC padding, and integer overflow in SC unambiguous ranges. Support unnamed CC/SC/SAB input streams and preserve station coordinates in standalone xradar sweeps. Keep internal Radar export independent of Py-ART imports; preserve optional metadata and array ownership when extracting sweeps.
- Preserve the active configuration when loading an incomplete replacement, and use the supported Matplotlib colormap default API.
- Prevent the web viewer from traversing symlinks outside its allowed roots or following directory cycles. Reject non-finite section coordinates.

## Compiled packages

The release includes 16 wheels: CPython 3.9, 3.10, 3.11, and 3.12 for Linux x86_64, Windows x64, macOS Intel, and macOS Apple silicon. Each wheel must pass installed-package tests and load the compiled `RadarGridC` extension before publication. A source distribution and SHA-256 manifest are also attached to the GitHub release.

```bash
python -m pip install --upgrade "pycwr[full]==1.0.9"
```

## Validation

The frozen source suite has 293 tests: 243 passed and 50 sample-dependent or optional slow tests skipped locally. Combined function tests and three real volumes executed all 474 public Python functions/methods/constructors, with 87.49% Python statement coverage. See the [validation record](https://github.com/YvZheng/pycwr/blob/v1.0.9/docs/releases/1.0.9-validation.md) for scope and reproduction steps.

Regression tests cover the repaired boundary cases. Three local WSR98D volumes were exercised through single-radar products, sections, QC, and HID. Export validation covers 261 WSR98D sweep/field comparisons, 162 MSG31 and 81 MSG1 comparisons through Py-ART, CfRadial round trips, xradar NetCDF writing, and viewer metadata/PPI/section endpoints.

Some older sample-specific tests require radar files that are not distributed with this repository and therefore remain skipped. WSR98D was checked by byte-header inspection and pycwr round trips; Py-ART was used as the independent reader for NEXRAD and CfRadial.

CC, SC, SAB, and PA readers also have synthetic binary protocol fixtures covering successful decoding, compressed/file-like input, and malformed files. These checks do not establish compatibility with every vendor variant. Public-function execution and test contexts can be audited with `scripts/audit_public_api.py`; see [the test guide](https://github.com/YvZheng/pycwr/blob/v1.0.9/test/README.md).
